# 24EC55 一页纸：生成式 AI 语言模型

> 本页速览 24EC55 的主要主题与知识入口。先看适用对象，再看核心义务；核对条款条件时转[详细导读](../regulatory/24EC55.md)和官方 PDF。本页不是机构执行清单。

## 适用对象

- 所有在**受规管活动**中使用 AI 语言模型或含模型产品的持牌法团：自研、集团提供、第三方、开源**均在范围内**（含 VATP 相关活动）。
- 对客提供投资建议 / 意见 / 研究的 AI 用例**一般属高风险**（售后服务类不在该句范围）。

## 核心义务速览（`[监管要求/期望]`）

| 主题 | 要点（保留原文条件） |
|---|---|
| 治理 | 全生命周期治理；高级管理层负责；集团委派不转移责任 |
| 验证 | 采用前及重大变更时适当验证；开发/验证/批准/持续检讨职能**可行且与风险相称时**分离 |
| 测试范围 | 从用户输入到输出的**完整链路**：含 RAG、过滤、提示管理 |
| 高风险对客 | 强化事实性验证；传达前**人审**（SFC 保留场景灵活性，非机构自行豁免）；提示变化稳健性；每次互动披露 AI 身份及可能不准确 |
| 监测 | 持续监测并成文；**有人审也不能停止测试/监测**；入侵识别；适当时暂停 |
| 对抗测试 | 定期进行、在可行范围内 |
| 数据 | 非公开资料静态/传输加密；训练数据质量；嵌入/向量服务隔离考虑 |
| 第三方 | 供应商尽调；黑箱适用性评估；开源不免其他控制；软件清单与中断预案 |
| 通知 | 重大业务性质/服务类别改变的通知义务；**不是**每个 AI 用例须先获批 |

## 常见误读（红线）

- ❌ 把"消除幻觉"的厂商宣传当结论 → 须独立核验
- ❌ 认为有人审即可豁免测试 → 第 19 段明确不可以
- ❌ 认为每个 AI 用例都要先报 SFC 批准 → 只有重大改变有通知义务
- ❌ 把附录风险因素当技术合规清单 → 附录是`[监管附录示例]`，非穷尽
