# 26EC32 一页纸：AI 增强网络威胁

> 本页先看适用对象，再速览网络安全措施和附录分层期望。具体范围与条款条件见[详细导读](../regulatory/26EC32.md)及官方 PDF；本页不设计机构执行流程。

**2026-06-02 发布。** 核实：2026-09-30。
[官方 PDF](https://apps.sfc.hk/edistributionWeb/api/circular/openFile?lang=EN&refNo=26EC32) · [详细导读](../regulatory/26EC32.md)

## 适用对象

- **所有持牌法团、SFC 持牌 VATP 及关联实体**——即使机构自己不用 AI 也适用（针对外部 AI 增强攻击）。
- 机构使用 AI 语言模型时另有额外要求，并衔接 24EC55。

## 核心义务速览（`[监管要求/期望]`）

| 主题 | 要点 |
|---|---|
| 责任 | 高管及 MIC-IT 最终负责；框架变更须检视批准并及时实施 |
| 资产清单 | 标注外露、业务关键、第三方依赖；更新速度须支持新情报下**当日**优先排序和遏制决定 |
| 假设失陷 | 按用户/设备/特权/网络可能失陷设计；最小权限；不可信输入不得改指令或触发特权；高影响动作 maker-checker |
| 漏洞 | 已知漏洞及时处理；紧急/关键修复有非例行流程；**没有统一补丁天数** |
| 监测 | 强化客户交易与系统活动异常监测及威胁情报 |
| 供应链 | 初始/持续供应链风险治理，考虑 AI 增强攻击 |
| 响应 | 响应和应变计划、快速升级、预先规划遏制；定期演练 |
| 备份 | 电子交易持牌法团和 VATP 至少每日备份；**不能扩展成所有机构统一每日** |
| 通知 | 按适用操守准则/VATP 指引及时通知重大网络安全事件 |

## 附录的分层期望（关键细节）

附录措施是非穷尽例子，**但**：电子交易持牌法团（特别大型零售券商）、第 13 类存管机构和
VATP **一般预期实施全部列出措施**；其他机构按业务性质、规模、复杂性考虑。
→ 不要把整份附录当成自由选配。

## 知识阅读入口

理解 AI 输入与攻击面的关系，可读[稳健性与安全](../concepts/robustness-and-security.md)；测试恶意输入可看[对抗测试](../methods/adversarial-testing.md)，测试工具权限边界可看[Agent 权限边界测试](../methods/agent-execution-boundary-test.md)。这些页面提供知识与方法，不替代通函的适用条件。


## 常见误读（红线）

- ❌ "我们不用 AI，与本通函无关" → 第 1、3 段不以自用 AI 为前提
- ❌ 自设"30 天补丁"当 SFC 标准 → 通函无统一天数，看风险相称与及时性
- ❌ 把"每日备份"推广到所有机构 → 仅电子交易与 VATP 明确至少每日
- ❌ 把附录提到的框架当作采购指令 → ISO、COBIT、NIST 在本页是参考例子，不是指定产品
