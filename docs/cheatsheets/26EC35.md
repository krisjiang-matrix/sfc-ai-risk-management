# 26EC35 一页纸：互联网交易强认证与异常监测

> 本页先看互联网交易专项范围，再速览认证、异常监测和分阶段时间表。范围疑问可查[适用范围矩阵](../regulatory/applicability.md)，原文条件见[详细导读](../regulatory/26EC35.md)；本页不提供机构账户处置流程。

**2026-07-09 发布，专项适用。** 核实：2026-09-30。
[官方 PDF](https://apps.sfc.hk/edistributionWeb/api/circular/openFile?lang=EN&refNo=26EC35) · [详细导读](../regulatory/26EC35.md)

## 适用对象与边界

- **互联网券商**（从事互联网交易的第 1/2/3 类持牌法团）及 **SFC 持牌 VASP**。
- 第 9 类资管**仅在通过互联网交易设施分销所管理基金的范围内**纳入。
- 普通内部投研/组合系统的资管公司，不因第 9 类牌照、互联网办公或使用 AI 而被纳入。

## 核心义务速览（`[监管要求/期望]`）

| 主题 | 要点 |
|---|---|
| 认证 | OTP **不视为**抗钓鱼方法；passkey 与稳健设备绑定为方案例子；设备绑定登录须另加认证因素 |
| 数量上限 | 一般不应超过 **3 个 passkey 及/或 3 个设备**；超过须适当评估（非绝对禁令） |
| 会话 | 不让客户关闭会话超时；30 分钟是示例，延长须有业务理由+密切监测 |
| 通知 | 及时通知成功登录及高风险账户活动；适用时多渠道 |
| 确认 | **强烈鼓励**重大变更/异常活动经客户确认后才继续交易 |
| 监测 | 交易阈值参考客户画像/历史、账户、设备、登录；红旗+设备日志+及时跟进 |
| 事件 | 黑客事件立即遏制、保护、通知客户、**立即报告 SFC**；后续详细报告+RCA+整改 |

## 时间表（不能全等到 2027）

| 要求 | 时限 |
|---|---|
| 客户通知、监测监督、响应/报告改进 | **立即检视改进** |
| 客户风险教育 | 尽快实施 |
| 强认证 | 尽快，**最迟 2027-07-08**；**大型互联网券商预期立即实施** |
| 预计难以按期 | **立即**通知个案主任 |

## 常见误读（红线）

- ❌ 把 OTP 当抗钓鱼认证 → 通函明确不视为
- ❌ 把 30 分钟会话超时当硬性监管数字 → 是示例，有条件可延长
- ❌ 设备原生指纹/面容解锁 = 附录的后台身份核验 → 不是一回事
- ❌ 大型机构也等 12 个月 → 大型互联网券商预期**立即实施**
