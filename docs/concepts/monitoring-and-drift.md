# 数据变化何时成为性能退化

输入语言比例变化、同一问题得到不同回答，以及规则更新后旧答案不再正确，是三种不同变化。它们可能同时出现，也可能彼此独立。**监测需要先说明变化对象，再用适合的参考数据判断是否影响任务质量，不能把所有告警都称为性能退化。**

## 总体错误增加，未必意味着同类任务退化

假设问答系统中文错误率为 10%，英文错误率为 30%。输入语言比例原来是 80% 中文、20% 英文，总体错误率为 0.8×10%＋0.2×30%＝14%。后来两种语言各占一半，总体错误率变为 20%。两种语言内部性能均未改变，整体错误增加来自较难输入占比上升。

这属于**数据漂移**：输入分布发生变化。语言、长度、主题或数值范围都可以作为观察对象。统计上有差异，说明两段数据不相同，并不能独立说明差异有害；新增一种系统擅长处理的主题，甚至可能提高总体质量。

因此，总体指标与分层指标应同时保留。如果英文比例增加，就要确认英文场景当前质量是否满足用途，而不是只寻找模型版本问题。反过来，总体不变也可能掩盖某个群组退化，被其他较容易的输入抵消。

## 输入分布、正确关系与系统行为分别观察

**概念漂移**指输入与正确结果之间的关系改变。例如同样询问某产品能否赎回，生效规则更新后正确答案改变。仅观察问题文字分布，可能看不出这种变化；需要当前规则或真实标签作为依据。

**行为漂移**指相同或相近输入下系统输出改变。固定问题与上下文重跑后答案变化，可能与模型、提示、参数、资料组装或随机性有关。远端服务名称保持相同，也不意味着内部行为条件始终相同；在没有相关证据时，不能直接指定变化源头。

| 变化类型 | 核验资料 | 可得到的结论 |
|---|---|---|
| 数据漂移 | 参考与当前输入的语言、主题等分布 | 可发现构成差异，不能单独确定正确率下降 |
| 概念漂移 | 输入、当前规则与可信标签 | 可检查正确结果关系变化；无标签通常不足 |
| 行为漂移 | 固定输入、上下文、输出与配置 | 可发现行为差异，仍需依据判断哪次正确 |

三者不能互相代替。资料更新可能既改变正确答案，又改变检索结果；此时固定旧参考答案继续评分，会把正确适应误判为退化。监测必须记录参考依据版本，判断变化来自应用还是评价标准。

## 固定基准与当前抽样提供互补证据

固定基准适合观察可比较条件下的版本变化，当前输入抽样适合判断实际任务构成。有可信结果标签的样本，才能进一步检查质量。只收集输入统计和延迟，无法直接得到事实正确率。

出现告警时，应核对窗口长度、样本量、缺失值与分层规则，再检查配置和资料更新。窗口太短可能只反映偶发波动；缺失输入被排除后，也可能改变比较对象。错误率上升还应确认标签是否延迟到达、分母是否变化，以及超时是否被计入失败。

案例中的语言比例变化可以用分层错误率解释；若固定中文题也明显变差，则需要进一步检查系统版本和调用过程。分布差异与质量退化可能同时成立，但其因果关系需要对照。诊断步骤见 [漂移诊断](../methods/drift-detection.md)、[变更回归](../methods/change-regression.md)及 [KRI 数据质量与回测](../methods/kri-data-quality-and-backtesting.md)。

## 辅助工具的能力与适用范围

分布分析、调用追踪和实验记录分别帮助发现变化、还原过程及比较配置。任何单个告警，都应回到实际质量和任务条件解释。

| 能力类别 | 工具定位与用途 | 使用限制 |
|---|---|---|
| 分布分析 | [Evidently](../tools/evidently.md) 可分析输入分布变化 | 无标签差异不能单独证明性能下降 |
| 调用链追踪 | [Phoenix](../tools/phoenix.md) 可观察请求及处理链路 | 采集范围决定可诊断环节 |
| 实验与版本记录 | [MLflow](../tools/mlflow.md) 可关联配置和比较结果 | 记录不替代当前标签与分层解释 |

这些工具为可选实现，不是 SFC 指定产品。监测结论只覆盖相应窗口、样本、版本与指标定义，不能用没有告警推断所有风险均未变化。
