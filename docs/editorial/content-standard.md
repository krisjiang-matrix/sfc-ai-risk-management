# 知识内容的编写标准

> 发布日期：2026-10-05。内容性质：知识库维护说明。

## 内容边界

本库解释 AI 风险概念、实现方法和现有工具，面向通用风险学习。不要编写机构组织职责、审批流程、固定工作频率、台账、底稿或新的工具。教学代码和现成工具的示例配置允许用于解释实现。

## 三类页面

| 类型 | 必须回答 | 深度要求 |
|---|---|---|
| 概念 | 是什么、为什么发生、何时适用、容易混淆什么 | 有机制解释和关联方法，不只是术语清单 |
| 方法 | 解决什么、输入与前提、怎么实现、怎么解释 | 至少一个可复核演算或合成对照；说明误报、漏报和限制 |
| 工具 | 支持什么方法、原理、输入输出、运行方式、数据去向、许可、替代路径 | 引用官方资料，注明版本和实测状态，不把扫描当合规认证 |

按内容需要组织章节，不要求统一十一节。专题页可以连接多个概念和方法，必须贡献实际教学价值，不能只是复制摘要。

## 阅读路径与教学用例

标题或开头应帮助读者判断页面回答什么问题。适合时先给一个短例子或主要结论，再解释机制、适用条件、依据和局限；不要求所有页面采用同一套小标题。专业术语第一次出现时就地解释，白话摘要不得比详细依据更确定，也不得添加依据中没有的数字或事实。

适合用测试用例教学的页面，建议明确目标组件、测试输入与前提、预期行为、实际观察及结论范围。涉及系统或工具时，应把模型回答、工具请求、权限控制决定和最终状态分开记录；比较防护效果时，同时检查正常任务是否仍能完成。案例中的公开事实、原始研究、专家判断和合成演示应能区分。

编辑推广要检查正文是否讲清机制、做法或判断依据，不能只改标题、摘要和相关阅读就算完成。适合时应重排正文论证，或让例子实际演示一次计算、对照或结果判断；页面已清楚时不为统一格式硬加内容。

采用[系统构成](../concepts/system-components.md)与[RAG](../concepts/rag.md)的阅读原则：导语说明实际问题与核心结论，正文以一个可核查案例串联原因、机制和判断。章节标题应描述具体内容，不以“是什么”“风险如何产生”“如何理解和实现”“常见误区与结果局限”作为所有页面的统一骨架。保留正常段落，每段解释一个有因果关系的观点；加粗用于突出关键区别，不能把正文压缩成零散要点。

流程图用于说明处理次序、分支或证据流向，表格用于对照条件、判据和结果；图表前后仍须解释其含义及结论范围。数值演算保留输入、中间过程和分母，不能用一个百分比替代论证。已有清楚的表格或代码示例时，不为视觉数量额外增加图形。

概念与方法页先说明遇到的问题及所需能力，再解释新概念，最后集中介绍可选软件的定位、用途与限制。避免把产品名散落在机制解释里，也避免“工具是什么”“在本文中能帮什么”等口语化表头。工具页自身则从任务缺口引出产品，连贯解释工作原理、数据流、配置与结果判读；名称出现不替代功能说明。

## 内容标签

| 标记 | 用途 |
|---|---|
| `[监管要求/期望]` | 原文所载要求或期望；给通函、段落/脚注/附录定位，保留适用范围、条件及措辞强度 |
| `[监管附录示例]` | 实际来自监管附录的例子；不得用于自行编写的演算 |
| `[技术解释]` | 对机制、指标及技术事实的解释；引一手文档或研究 |
| `[参考方法]` | 可选择的实现、评测或分析方法；不等于 SFC 指定方法 |
| `[教学示例]` | 自行构造的合成数据、情境、阈值和配置；说明教学边界 |
| `[可选工具/框架]` | 现有软件、标准或框架；不是监管采购清单 |

混合内容分段标记。通用术语可在页首标为技术解释，不必每句贴标签。涉及监管与教学的切换需要明确标记。不能把待核实内容写成已核实结论。

## 来源与版本

原文引用须有精确定位和官方链接。技术解释优先官方文档或原始研究。将关键来源登记到[来源登记册](../source-register.csv)，含核实日期、版本和状态；仅访问入口不等于读完全文。

发布日期与来源核实日期分开。重排文字不能更新来源核实日期。移动版文档标注访问日期；工具 API 和命令写清适用版本，未运行的注明“文档核对，未实测”。无法确认时记录缺口，不编造提交哈希、测试结果或维护状态。

## 演算与结论

说明分子、分母、统计单位、缺失/不适用和样本排除规则。提供输入、中间步骤与结果；避免用样本零失败推导绝对安全。阈值只有在原文明确规定时才能称为监管阈值。替代方案应说明能力损失，不能宣称一个工具解决全部风险。

合成数据不得含真实客户、交易、日志或凭据。教学场景不必虚构整家公司的制度。

## 发布检查

更新[覆盖矩阵](../coverage.md)的实际深度。新增活动页面加入主导航；迁移页面登记迁移关系并从菜单移除。运行完整性检查和严格构建，再人工复核关键知识链的来源、演算和结果局限。
