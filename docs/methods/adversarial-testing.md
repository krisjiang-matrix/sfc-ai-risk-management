# 对抗测试：攻击路径、执行结果与覆盖范围

正常问题答得正确，不能说明系统在恶意输入下仍守住边界。**对抗测试通过受控的恶意或异常输入，检查任务指令、数据访问、模型行为和工具动作是否被改变。** 评估对象通常是完整应用；模型输出拒绝语句，并不代表检索、日志或执行端没有暴露数据。

<p class="article-meta">参考方法 · 本文更新：2026-10-11 · 案例为合成教学材料，未运行攻击工具或模型。</p>

SFC生成式AI通函对高风险模型的测试要求及适用条件见[24EC55原文导读](../regulatory/24EC55.md)。以下攻击分类与测试设计属于技术参考，不能把所有类别视为每个用例都须采用的固定清单，也不提供统一成功率阈值。

## 不可信资料如何沿调用链改变行为

教学任务是总结公开资料。检索文档中混入要求读取虚构内部记录并外发的文字。模型可能仍然生成正常摘要，也可能把资料内容误当成指令，进而提出工具调用。越界提议之后，执行器是否按身份、对象和参数拒绝请求，决定了提议是否成为实际动作。

| 链路环节 | 核验依据 | 结果解释 |
|---|---|---|
| 检索与上下文 | 进入模型的实际资料 | 攻击内容是否被系统处理，而非只存在于资料库 |
| 生成与计划 | 回答、拟调用与参数 | 模型是否将资料当成新指令 |
| 授权与执行 | 权限决定、实际调用 | 是否拦截越界请求或执行了非预期动作 |
| 最终状态 | 记录读取、外发状态与正常摘要 | 是否造成影响，允许任务是否仍然完成 |

模型提出越界动作却被执行端拒绝，与攻击完全没有影响模型，是不同发现。应记录输入、系统和模型版本、语言、预期行为、实际输出、工具调用、授权决定和最终状态；不能把工具报错或服务中断都归为防护成功。完整用例见[提示注入教学专题](../topics/prompt-injection.md)。

## 攻击目标决定测试条件与观察对象

**提示注入**针对应用的指令边界。直接注入出现在用户输入，间接注入来自检索资料、网页、邮件或工具返回。测试需控制注入位置、访问身份和预期任务，并检查不可信内容是否获得指令权限。虚构canary标记可以帮助观察泄漏路径，但没有出现标记不证明所有内容都未暴露。

**越狱**侧重绕过模型的安全限制，与提示注入可能重叠，但二者不宜简单归为固定上下级关系。角色话术、编码混淆、多轮渐进、长上下文示例，以及自动搜索提示，分别探索不同失败路径。梯度优化需要白盒或相应接口条件；黑盒应用不能因为某种攻击无法执行，就被判定不存在该风险。

**对抗样本**改变输入表征，例如图像、音频扰动或文本字符替换，使感知或分类结果变化。它与文档中的恶意任务指令不同。白盒方法可利用模型梯度，黑盒方法依赖查询或迁移；扰动强度、可访问接口和正常任务结果都应记录，避免只展示攻击后错误而没有原始对照。

**模型抽取**通过查询输出建立替代模型，观察目标能力可被复制的程度；**训练内容提取**则尝试使模型输出记忆的内容。两者不应混同，查询预算、目标接口和替代模型的比较任务决定结果含义。**成员推断**仅判断一条资料是否参训，不要求提取原文，需有已知成员与匹配的非成员作为对照。

**数据投毒**改变训练或检索数据。训练投毒可能影响参数或后门行为，检索资料污染可能让回答依据错误证据或接收间接注入。测试应区分污染源、进入阶段及实际使用情况，不能把文档被加入资料库直接等同于攻击成功。

**Agent工具滥用**涉及越权调用、参数篡改、重复动作、外泄通道或多工具组合。只读工具也可能泄漏信息，高影响动作的控制应结合应用边界与适用要求。隔离环境中的具体观察见[Agent执行边界测试](agent-execution-boundary-test.md)，隐私攻击判据见[隐私测试](privacy-testing.md)。

## 攻击成功率需要明确计数与成功判据

攻击成功率通常表示满足预定失败条件的攻击次数占实际测试次数的比例，但计量单位必须固定。一个基础问题的多轮搜索、多个变体和多次重试可能相关；不能把预算更大的攻击器与单次尝试直接按同一分母比较。

成功判据应对应攻击目标。生成禁用内容、提出越界工具调用、取得未授权资料和完成外发是不同事件；文本裁判只读取回答时无法证明后两项。正常对照用于检查系统是否仍能完成允许任务，自动发现则需要人工或确定性状态证据复核，以区分误报和漏报。

测试未发现失败，仅支持所选模式、预算、版本和条件下的观察。公开基准可能与产品资料、权限和多轮业务差异很大；它们适合提供攻击样式或比较条件，不能独立证明应用安全。不同语言、工具组合和资料位置应按用途设计覆盖，而非机械堆叠攻击数量。

## 辅助工具与基准的能力和适用范围

批量探针用于扫描已有攻击样式，自适应编排用于迭代和组合输入，鲁棒性工具用于模型级扰动与隐私研究。运行时防护属于被测控制，不等于测试框架；启用防护后仍需观察实际数据与动作。

| 能力类别 | 工具定位与用途 | 使用限制 |
|---|---|---|
| 已知提示与泄漏扫描 | [garak](../tools/garak.md)；[官方项目](https://github.com/NVIDIA/garak)提供探针 | 探针命中需复核，不能覆盖全部业务或执行权限 |
| 应用评估与攻击编排 | [Promptfoo](../tools/promptfoo.md)、[PyRIT](../tools/pyrit.md)、[FuzzyAI](https://github.com/cyberark/FuzzyAI)支持不同编排方式 | API、工具适配及多轮状态需与被测应用一致 |
| 对抗扰动与模型隐私研究 | [ART](https://github.com/Trusted-AI/adversarial-robustness-toolbox)、[TextAttack](https://github.com/QData/TextAttack)、[CleverHans](https://github.com/cleverhans-lab/cleverhans)、[Foolbox](https://github.com/bethgelab/foolbox) | 可用攻击依赖模型、数据形态与接口，不是通用语言模型扫描器 |
| 隐私审计及训练研究 | [ML Privacy Meter](https://github.com/privacytrustlab/ml_privacy_meter)、[TensorFlow Privacy](https://github.com/tensorflow/privacy) | 需要确认训练与攻击条件，不能凭分数识别真实个人参训 |
| 内容防护 | [Lakera Guard](https://www.lakera.ai/)、[Vigil](https://github.com/deadbits/vigil-llm)、[Rebuff](https://github.com/protectai/rebuff)提供不同检测实现 | 防护存在漏检与误拒，不能替代底层授权 |

公开基准用于固定任务与比较条件。原资料中的 [AdvBench](https://github.com/llm-attacks/llm-attacks)以500条有害指令示例介绍，[JailbreakBench](https://github.com/JailbreakBench/jailbreakbench)以100种行为介绍；具体版本、子集与评分规则应在实际使用时核对，不能把页面数字视为当前工具规格。[HarmBench](https://harmbench.org/)提供行为评判与攻击基线，[AgentDojo](https://github.com/ethz-spylab/agentdojo)提供代理安全场景。应用测试还需要自己的授权、资料与最终状态判据。
