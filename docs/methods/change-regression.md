# 变更回归：用配对结果定位能力变化

更换模型、提示或检索配置，可能修复一类错误，同时引入另一类错误。**变更回归用相同问题和判据逐题比较两个版本，分别记录新增失败、改善与持续失败。** 平均分数描述净变化，无法独立说明权限、例外条件或关键数值是否退化。

SFC 24EC55第13(b)段涉及设计、假设、输入、计算或输出有重大改变时的适当验证，适用原文见[通函导读](../regulatory/24EC55.md)。以下方法说明如何建立可比较证据，不制定机构上线审批标准。

<p class="article-meta">参考方法 · 本文更新：2026-10-11 · 来源核实：2026-09-30 · 合成教学材料，未执行测试，不构成统一阈值、频率或职责要求。</p>

## 同题比较需要固定资料、判据与版本

假设产品问答系统更新检索配置，希望改善例外条款召回。旧版与新版应使用同一问题、允许资料、身份和评分规则；若同时更新资料或参考答案，应明确这些因素，不把整组变化归因于单一组件。

<div class="method-comparison-table" markdown="1">

| 输入项 | 说明 | 数据来源示例 |
|--------|------|--------|
| 金标准测试集 | 固定的、有预期答案的测试数据集（含版本快照） | 测试记录（参见 [gold-standard-design.md](gold-standard-design.md)） |
| 变更前系统的输出 | 变更前版本对金标准测试集的完整响应 | 版本化输出及运行元数据 |
| 变更后系统的输出 | 变更后版本对同一金标准测试集的完整响应 | 版本化输出及运行元数据 |
| 变更说明 | 记录模型版本、提示变化、配置修改等对比因素 | 变更内容和配置差异 |
| 变更前基线指标 | 变更前的参考源核验通过率、检索质量等观测 | 指标定义、分母和原始结果 |

</div>

金标准及旧版输出应可复核。记录并尽量保持非目标因素一致，重复运行也保留条件；相同种子和温度设置不保证完全确定。系统数据与权限状态不同，会破坏表面上相同问题的可比性。

## 逐题配对显示新增失败与改善

使用同一批100个问题，旧版本错10题、新版本错16题。配对明细为6题旧错新对、12题旧对新错、4题两版均错、78题两版均对。

<div class="method-comparison-table" markdown="1">

| 观测 | 数值 | 解读 |
|---|---:|---|
| 旧版整题通过率 | 90/100 = 90% | 每题按同一答案标准判一次 |
| 新版整题通过率 | 84/100 = 84% | 下降6个百分点 |
| 新增失败 | 12题 | 检查具体错误类型与影响 |
| 改善 | 6题 | 保留改善案例，不只看退化 |

</div>

模型版本、测试集、提示、索引与评分规则同时记录。指标不能直接决定上线与否，也不能凭一次配对实验断言变化根因。回归比较是知识方法，不是机构审批报告。

因此调查不应止于“下降6个百分点”。12个新增失败说明具体受影响的场景，6个改善说明修复有效的位置；二者需要分别追溯来源、上下文和执行结果。

## 事实、检索与权限需要独立比较

在变更前，保存以下快照：

<div class="method-comparison-table" markdown="1">

| 快照内容 | 保存方式 |
|----------|----------|
| 金标准测试集的完整输入 | 固定不变 |
| 变更前系统的所有输出 | 每条输出与测试用例ID关联 |
| 变更前各维度指标 | 参考源核验通过率、检索Recall@k、引用准确率等 |
| 系统配置信息 | 模型版本、系统提示、温度参数、RAG配置等 |

</div>

每个快照有唯一版本号（如 `v20260930-001`）；快照存储为只读格式，不可修改；快照与变更描述关联（知道从什么变到了什么）。

**关键：** 使用与变更前完全相同的测试输入、参数和配置（除已变更的部分外）。

对每条测试用例，逐条比较变更前后的输出：

<div class="method-comparison-table" markdown="1">

| 比较维度 | 方法 | 判定 |
|----------|------|------|
| **事实核验** | 同一问题的可核验声明按相同规则配对评分；同时报告旧对新错、旧错新对的数量 | 记录差异幅度与不确定性；没有通用的百分点触发线 |
| **新引入错误** | 列出变更前通过、变更后未通过的具体案例和影响 | 每个新失败都应复核；严重度由错误后果和应用边界决定，不由单个计数自动决定 |
| **已修复错误** | 列出变更前未通过、变更后通过的配对案例 | 与新增失败并列报告，不能只用净分数抵消关键失败 |
| **检索质量** | 同一 RAG 问题比较相关文档、排名、有效日期和访问权限 | 说明缺失或新增的资料及其影响；平均召回不能抵消越权结果 |
| **权限行为** | 对同一主体、对象和权限策略比较实际执行结果 | 发现任何新的越权路径都应调查并记录影响；是否构成阻断取决于既定安全边界 |
| **输出格式** | 比较输出结构和应用要求的披露项 | 说明变化是否破坏用途；关键缺失需结合具体使用情境判定 |

</div>

比较错误的影响与发生条件，例如越权、错误数值和关键遗漏，而非采用固定严重度矩阵。每个快照使用唯一标识并保留版本；只读格式有助避免误改，但不能独立证明源记录真实。

## 平均质量改善不能抵消权限缺口

某合成 RAG 系统更新了 embedding 模型，期望改善检索质量；以下固定测试记录只用于演示跨维度比较。

<div class="method-comparison-table" markdown="1">

| 指标 | 变更前 | 变更后 | 变化 |
|------|--------|--------|------|
| 整题通过率（同一100题，每题按同一标准判一次） | 85/100 = 85% | **87/100 = 87%** | +2pp |
| 平均 Recall@3（同一100题，每题计算后等权平均） | 78% | **82%** | +4pp |
| 权限检查通过率（同一100组主体—文档请求） | 100/100 = 100% | **60/100 = 60%** | -40pp |

</div>

整题通过率的配对明细为：5题从未通过变为通过、3题从通过变为未通过、92题状态不变；因此 85+5-3=87，净变化为+2题（+2pp）。权限检查中，100组相同请求原先全部通过、新版本有40组未通过检查；这表示40组行为发生变化，不等于已经证明发生40次越权。必须逐项核对主体、请求文档、授权策略、实际返回内容和最终输出，区分数据暴露、错误拒绝及其他失败路径。

Recall@3 的表中值是每题先计算 `相关文档命中数@3 ÷ 期望相关文档数` 再对100题等权平均；没有逐题结果，无法复核平均值的不确定性或判断哪些检索发生变化。

新的 embedding 模型改变了候选文档排序，可能让原先未进入结果的受限文档出现；但向量相似度本身不应授予访问权限。只有在授权过滤缺失、位置错误或主体—文档策略映射不一致时，候选结果才可能变成真实泄漏。该汇总本身不能证明根因。

平均指标改善不能抵消权限检查的下降；应核对身份、对象和执行端授权的逐例证据，再确认是否发生真实越权。不能仅凭相关性把结果归因于 embedding 变化。

回归测试不能只看平均值。各维度应独立分析，特别是安全相关维度（权限、数据泄露、对抗鲁棒性）。

## 重复运行区分单次波动与持续差异

同一批测试问题在五轮重复运行中的整题通过率（每题按同一答案标准判一次，教学数据）：

<div class="method-comparison-table" markdown="1">

| 运行 | 变更前准确率 | 变更后准确率 |
|------|-------------|-------------|
| Run 1 | 90% | 80% |
| Run 2 | 85% | 88% |
| Run 3 | 88% | 85% |
| Run 4 | 83% | 86% |
| Run 5 | 87% | 84% |
| **平均** | **86.6%** | **84.6%** |

</div>

单看 Run 1，准确率从 90% 降至 80%（-10pp）；五轮均值从 86.6% 到 84.6%（-2pp）。本例五轮的变化方向不一致，但汇总值没有逐题配对信息，不能判定差异来自随机性，也不能排除真实退化。应补充逐题配对结果，并根据波动和需识别的差异规划重复次数与不确定性分析。

接口支持时保留种子、温度与时间，按相同问题和规则重复运行，查看逐题差异分布。3–5次可用于教学展示，正式次数依据波动与希望识别的差异设计；温度为零也不保证确定。

## 结论适用于已覆盖场景与比较条件

固定测试集未覆盖的新型问题无法由这次回归发现。平均改善不能排除关键退化，无失败观察也不证明总体没有退化。结果应同时给出配对案例、重复运行、不确定性及版本条件。
