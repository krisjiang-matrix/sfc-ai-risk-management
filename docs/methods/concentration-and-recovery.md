# 依赖中断与恢复验证：恢复可用仍需检查结果质量

三个应用显示为独立服务，却可能依赖同一个模型接口、云区域或鉴权系统。这个共同节点中断，会使多个用途同时失效。**恢复验证先识别共同故障路径，再观察检测、切换与数据恢复，最后核对备用路径的输出和权限。** 服务返回响应，不等于恢复到正确状态。

24EC55第25段涉及数据完整性，26EC32第11段涉及关键组件管控，适用条件见[24EC55](../regulatory/24EC55.md)和[26EC32](../regulatory/26EC32.md)导读。具体依赖图、时间目标和故障注入是本文的参考方法。

<p class="article-meta">参考方法 · 本文更新：2026-10-11 · 来源核实：2026-09-30 · 合成教学材料，未执行测试，不构成统一阈值、频率或职责要求。</p>

## 共同依赖需要从应用清单追踪到底层路径

某合成系统列出三个 AI 用例，其上游依赖如下：

<div class="method-comparison-table" markdown="1">

| 依赖项 | 用例A（投顾建议） | 用例B（客服FAQ） | 用例C（内部合规检索） |
|--------|-----------------|-----------------|---------------------|
| LLM API | 提供商A | 提供商A | 提供商A |
| 向量数据库 | 内部（主） | 内部（主） | 内部（主） |
| 客户数据 | 内部API | 内部API | N/A |
| 市场数据 | 提供商B | N/A | N/A |

</div>

**可观察的信号：** 列出的用例中有 3/3 依赖同一个 LLM 提供商。若该依赖中断，三个用例可能同时受影响，这是共同故障路径；此小清单不能证明它覆盖全部系统，也不足以量化更广泛的系统性风险。

**可能的比较方向（教学示例）：** 可比较不同提供商、经过验证的本地回退，以及不依赖生成模型的有限功能路径；选择取决于用例影响、权限和恢复后质量证据，不由本例指定统一方案。

替代供应商也可能共享云区域、网络或认证依赖，应继续追踪底层路径。依赖清单说明可观察集中度，但在未核实全部应用和调用关系前，不能宣称覆盖完整。

## 恢复目标与备用路径需要事先可核验

<div class="method-comparison-table" markdown="1">

| 输入项 | 说明 | 数据来源示例 |
|--------|------|--------|
| 系统架构与依赖信息 | 上游 API、数据库、服务、共同云/区域和鉴权路径 | 架构图、依赖清单 |
| 服务目标 | 该用例适用的恢复时间和可接受数据丢失范围 | 已定义的 RTO/RPO 或其他服务目标 |
| 恢复路径 | 故障时的备用依赖、回退行为和恢复后状态 | 配置、运行记录或可验证的恢复描述 |
| 历史中断证据 | 过去中断的影响、持续时间及恢复结果 | 事件时间线和运行日志 |

</div>

测试在隔离环境中模拟，不损坏生产数据；准备固定质量题目、状态核对和运行记录。RTO表示从故障发生到恢复可用的目标时间，RPO表示可接受的数据丢失窗口，二者不同于切换后的答案质量。

创建AI系统的依赖关系图：

```text
AI系统
├─ LLM API（商业提供商A）
│   └─ 无替代方案 ← 单点故障
├─ 向量数据库（内部部署）
│   └─ 替代：只读副本 ← 有降级路径
├─ 客户数据API（内部微服务）
│   └─ 替代：缓存层（30分钟过期） ← 有限降级
├─ 身份认证服务（内部SSO）
│   └─ 替代：备用认证服务器 ← 有降级路径
└─ 市场数据源（第三方提供商B）
    └─ 替代：提供商C ← 有替代供应商
```

<div class="method-comparison-table" markdown="1">

| 依赖项 | 数据来源示例 | 单一供应商？ | 是否有替代？ | 降级影响 | 集中度风险 |
|--------|--------|------------|------------|---------|-----------|
| LLM API | 商业提供商A | 是 | 否 | 系统完全不可用 | 🔴 高 |
| 向量数据库 | 内部 | N/A | 只读副本 | 检索降级为只读 | 🟡 中 |
| 客户数据API | 内部微服务 | N/A | 30分钟缓存 | 数据最多延迟30分钟 | 🟡 中 |
| 身份认证 | 内部SSO | N/A | 备用服务器 | 无影响 | 🟢 低 |
| 市场数据 | 第三方B | 是 | 提供商C | 切换到C（数据格式可能不同） | 🟡 中 |

</div>

上面的现状中主模型尚无备用。下面列出可供设计和验证的候选回退路径，并不表示这些路径已经实现；每条路径都需独立检查共同依赖与恢复后质量。

<div class="method-comparison-table" markdown="1">

| 依赖项 | 降级方案 | 降级后的功能限制 |
|--------|----------|-----------------|
| LLM API 不可用 | 切换到备用LLM提供商 | 模型行为可能略有差异 |
| LLM API 和备用均不可用 | 回退至基于规则的响应 | 丧失AI生成能力，仅返回预定义回复 |
| 向量数据库不可用 | 切换至只读副本 | 检索结果可能不是最新 |
| 客户数据API不可用 | 使用缓存数据（30分钟内） | 客户数据可能有最多30分钟延迟 |
| 客户数据API长时间不可用 | 人工提供客户数据 | 服务效率严重下降 |

</div>

为每个AI用例定义：

<div class="method-comparison-table" markdown="1">

| 参数 | 定义 | 示例（高风险对客AI） | 示例（内部辅助AI） |
|------|------|---------------------|-------------------|
| **RTO (Recovery Time Objective)** | 从故障发生到系统恢复可用的最大允许时间 | 4小时 | 24小时 |
| **RPO (Recovery Point Objective)** | 可接受的最大数据丢失窗口 | 15分钟 | 4小时 |

</div>

**解释：** RTO/RPO需结合业务影响与技术可行性；表中时间仅用于教学，不是按用例风险等级给出的统一要求。

## 故障模拟同时检查切换、数据与权限

恢复测试应在测试环境中执行，模拟故障并验证恢复过程。

<div class="method-comparison-table" markdown="1">

| 场景 | 模拟故障 | 验证目标 |
|------|----------|----------|
| LLM API中断 | 阻断对提供商A的API调用 | 系统是否自动切换到备用提供商？切换时间是否在RTO内？ |
| 向量数据库故障 | 停止向量数据库实例 | 系统是否切换到只读副本？切换后检索结果是否可接受？ |
| 全部LLM不可用 | 阻断所有LLM API | 系统是否回退到基于规则的响应？客户体验是否可接受？ |
| 数据恢复 | 模拟数据损坏 | 从备份恢复的数据是否完整？恢复时间是否在RTO内？ |

</div>

系统恢复后，使用金标准测试集验证恢复后的输出质量：

<div class="method-comparison-table" markdown="1">

| 检查项 | 方法 | 结果解释 |
|--------|------|-----------|
| 参考源核验通过率 | 使用金标准测试集运行并对比基线 | 报告分母、基线差异、错误类型与不确定性 |
| 权限控制 | 运行权限测试用例 | 检查是否出现新越权；样本全通过不证明总体零风险 |
| 响应时间 | 测量端到端响应延迟 | 比较原定服务目标及实测延迟分布 |
| 功能完整性 | 运行功能测试清单 | 所有核心功能可用 |

</div>

## 备用模型的答案需要同题复核

用同一固定测试集比较主模型与备用模型，分别报告事实错误、引用支持、拒答、权限隔离和延迟。观察到零错误只说明样本中未发现错误，不能证明总体错误率为零。

关键数值可通过源数据直出、确定性计算及引用核验降低生成错误；是否限制自由生成，取决于应用用途与错误影响，不能由本库规定统一红线。检验备用模型是否错误接受信息不足或越界请求，以及切换后是否损坏数据权限。

[技术解释] 降级提示可帮助用户理解能力变化。24EC55 第17、18(d)段的 AI 身份和可能不准确披露应保留适用条件；原文没有规定本页此前建议的统一应急水印文本。

某合成恢复测试切换到备用 LLM 提供商后，质量检查记录为：

参考源核验通过率从88%（主路径）降至81%（备用路径）；差异为-7个百分点；分母和逐题配对结果未给出。

**待验证假设：** 备用模型、提示适配或检索整合可能不同；汇总分数不能确定根因。只有在同一问题和评分规则下逐项配对，才能定位哪些案例变化；未给分母时不能评估差异不确定性。

**教学解释：** 对同一测试集进行逐题配对比较，检查事实错误类型及输出分布，再对候选回退路径复测。自动与人工切换的差异不等同模型质量改善。

## 时间线与质量差异支持不同结论

下列观测只演示如何把恢复时间、输出质量与服务目标分开判断：

<div class="method-comparison-table" markdown="1">

| 观测 | 计算或参照 | 可得结论 |
|---|---|---|
| LLM API 中断后，15秒检测、30秒切换 | 总恢复时间 = 15+30 = 45秒；教学假设的 RTO 为4小时 | 本次模拟的45秒小于该示例目标；不能外推至其他故障或生产负载 |
| 恢复后参考源核验通过率87%，基线88% | 变化 = 87%-88% = -1个百分点 | 未提供样本量与预设容忍范围，不能仅凭该差值判定通过或失败 |
| 权限测试通过率100% | 分母和逐例执行状态未给出 | 只能说当前展示值为100%；无法复算，也不能据此证明总体零越权 |
| 响应时间2.3秒，基线2.0秒 | 增加0.3秒，即15% | 本例没有服务目标上限；只能报告观测差异。判断前还需比较重复请求的延迟分布 |
| 所有 LLM API 中断后，5秒内返回不可用提示 | 文字提示：“系统暂时无法处理复杂请求，请使用经确认的替代服务渠道。” | 说明系统返回了提示；是否满足目标、替代渠道是否有效，仍需相应证据 |

</div>

这里的时间与比率都是合成参数，不代表统一 RTO、SLA 或验收线。复测应由依赖、架构、恢复路径变化及先前证据驱动，不设固定周期。

故障注入、检测、切换和完成恢复的时间戳应关联同一次试验，并保留恢复后逐题结果。供应商承诺和配置中的备用路径不能替代实际验证；权限测试通过率没有分母和执行状态时，也无法复算。

## 有限故障演练不能外推所有生产条件

测试负载、数据量与网络条件可能不同于生产，局部降级、级联故障和沉默错误也未必被单次演练覆盖。备用路径存在不说明用户能获得所需服务；应解释能力限制，并检查替代渠道是否真正可用。

集中度概念见[第三方与韧性](../concepts/third-party-and-resilience.md)，数据边界见[数据与隐私](../concepts/data-and-privacy.md)，安全与恢复交互见[鲁棒性与安全](../concepts/robustness-and-security.md)。本方法不绑定软件，隔离故障注入、状态核对和逐题记录共同提供证据，单一监控面板不能证明恢复正确。
