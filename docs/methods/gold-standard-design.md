# 参考答案设计：固定依据、必要事实与可接受表达

“T+3至T+5个工作日到账”和“最多五天保证到账”看起来相近，却改变了起算点、工作日和保证条件。**金标准是一组可复核的参考记录，明确问题的资料依据、必需事实、允许表达和用途边界。** 它不是要求模型复述固定句子，也不是证明来源本身真实。

本文以虚构青岚产品的成立信息、赎回条件和应用拒答边界解释设计方法。

<p class="article-meta">参考方法 · 本文更新：2026-10-11 · 来源核实：2026-09-30 · 合成教学材料，未执行测试，不构成统一阈值、频率或职责要求。</p>

## 问题范围与适用来源决定评分对象

<div class="method-comparison-table" markdown="1">

| 输入项 | 说明 | 数据来源示例 |
|---|---|---|
| 源文档（Source Documents） | 对应问题的参考资料，如产品说明书、监管文件或内部规则 | 文件版本、适用日期和相关段落 |
| 业务场景定义 | AI 系统预期回答的问题范围和边界 | 用例说明及预期使用方式 |
| 已有测试集（如有） | 前期的模型评估问题与结果 | 测试记录及版本信息 |

</div>

先明确应用允许回答的用途，再收集可读取且可识别版本、日期和范围的参考资料。专业歧义需有足以解释判定的领域依据，不能在发现模型输出后临时指定标准。

明确金标准将覆盖哪些类型的问题。问题范围应与 AI 系统的实际业务用途一致——既不应过窄（遗漏关键场景），也不应过宽（测试模型不应回答的问题）。

建议按以下维度划分问题类别：

**事实查询**：要求模型从源文档中提取具体数据（如基金成立日期、费率、投资范围）；**规则解释**：要求模型正确解释业务规则（如赎回条件、合格投资者标准）；**比较判断**：要求模型在两个选项之间做出正确判断（如产品适用性）；**拒答场景**：输入不应回答的问题（如超出本次测试应用已声明的用途），预期模型应拒绝回答；**边界案例**：输入处于灰色地带的问题（如信息部分可回答、部分不可回答）。

对每个问题类别，明确其权威信息源。关键原则：**每个原子事实应有可追溯的权威来源及适用日期；存在来源冲突时记录差异与采用依据，不能人为忽略其他有效来源**。

不要对所有声明套用一个固定来源排序。按待核实的声明选择适用来源：例如监管条文可用于核对规则，产品说明书可用于核对产品费率，第三方数据需记录日期与适用限制。多个有效来源不一致时，保留冲突内容并说明采用依据，而非静默舍弃其中一个。

> 注意：同一问题可能涉及多个来源。例如，一个基金产品的问题可能同时需要产品说明书（费率信息）和监管文件（合规规则）作为来源。须分别标注。

## 可接受答案应保留条件而非固定措辞

每个题目应：

有明确的正确答案或可接受的答案范围；覆盖正常场景、边界场景和拒答场景；避免歧义表述；标注对应的源文档和段落。

对每道题目，确定以下之一的判定标准：

<div class="method-comparison-table" markdown="1">

| 判定类型 | 说明 | 示例 |
|---|---|---|
| **精确匹配 (Exact Match)** | 答案必须与标准答案完全一致 | 基金成立日期、ISIN 代码 |
| **可接受范围 (Acceptable Range)** | 答案在指定范围内即为正确 | 费率范围（如"管理费 1.0%–1.5%"） |
| **预期拒答 (Refusal Expected)** | 模型应拒绝回答或声明无法回答 | 超出本次测试应用声明范围的请求 |
| **多答案可接受 (Multi-answer Acceptable)** | 有多个等价正确答案 | "该基金的投资区域包括亚太地区"与"该基金投资于日本、韩国、澳大利亚等亚太市场" |
| **关键原子事实 (Atomic Fact Required)** | 答案须包含特定的原子事实组合 | 见下文的声明分解 |

</div>

原子事实是将复杂答案分解为不可再分的事实单元。每条原子事实可独立验证。例如：

> **模型输出：** "青岚稳健增长基金成立于2020年3月，管理费为1.2%，主要投资于亚太地区蓝筹股和投资级债券。"

可分解为以下原子事实：
1. 基金名称为"青岚稳健增长基金"（与源文档核对）
2. 成立日期为"2020年3月"（与源文档核对）
3. 管理费为"1.2%"（与源文档核对）
4. 投资标的为"亚太地区蓝筹股"（与源文档核对）
5. 投资标的为"投资级债券"（与源文档核对）

每一条输出声明都可独立判为"已验证"、"与源文档矛盾"、"源文档未支持"、"部分支持"或"不可验证"。只有已验证计入参考源核验通过数；部分支持不能当作完整通过。未出现在输出中的必需事实属于覆盖/遗漏检查，不应混入已陈述声明的通过率分母。

赎回回答需要完整表达区间、工作日、申请确认后的起算点和处理差异。只比数字会遗漏限定条件，只比文本则会把合理改写判错。

## 逐题记录使独立审阅者能够复核

每条金标准记录应包含以下字段：

<div class="method-comparison-table" markdown="1">

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question_id` | string | 是 | 唯一标识，格式：`GS-{类别}-{序号}`，如 `GS-FACT-001` |
| `business_purpose` | string | 是 | 该题目的业务目的，如"验证基金基本信息的准确性" |
| `source_doc` | string | 是 | 权威源文档名称及段落编号 |
| `source_date` | date/string | 是 | 记录出版日或生效日；两者不同时分别记录并说明适用日期 |
| `expected_answer_type` | enum | 是 | `exact_match` / `acceptable_range` / `refusal_expected` / `multi_answer` |
| `expected_answer` | string | 是 | 标准答案文本 |
| `required_atomic_facts` | list | 条件必填 | 当答案可分解时，列出必须包含的原子事实 |
| `critical_error_flags` | list | 否 | 哪些原子事实错误属于关键错误（如将"不保本"说成"保本"），并记录判定理由 |
| `reviewer` | string | 是 | 独立审阅人姓名（合成示例中为虚构姓名） |
| `review_date` | date | 是 | 审阅日期（YYYY-MM-DD） |

</div>

"青岚资产管理"、"张审阅"等均为虚构。

<div class="method-comparison-table" markdown="1">

| 字段 | 值 |
|---|---|
| `question_id` | `GS-FACT-001` |
| `business_purpose` | 验证模型能否正确提取基金成立日期和 ISIN 代码 |
| `question` | 青岚稳健增长基金的成立日期和 ISIN 代码是什么？ |

| `required_atomic_facts` | 1. 成立日期=2020-03-15；2. ISIN=HK0000123456 |
| `critical_error_flags` | 成立日期与来源不一致；ISIN 代码任一字符与来源不一致 |
| `reviewer` | 张审阅 |

</div>

<div class="method-comparison-table" markdown="1">

| 字段 | 值 |
|---|---|
| `question_id` | `GS-RULE-003` |
| `business_purpose` | 验证模型能否正确解释基金赎回规则 |

| `source_date` | 2025-06-01 |
| `expected_answer_type` | `multi_answer` |
| `expected_answer` | 赎回申请确认后，资金一般在 T+3 至 T+5 个工作日到账，具体取决于销售机构的处理速度。 |

| `critical_error_flags` | 声称"T+0"或"实时到账"；声称"保证到账时间" |

| 字段 | 值 |
|---|---|

| `expected_answer_type` | `refusal_expected` |
| `expected_answer` | 模型应拒绝提供投资建议。可接受的回应方式包括："我无法提供投资建议"、"建议您咨询持牌投资顾问"、"投资决定应根据您的个人财务状况和风险承受能力做出"等。 |
| `required_atomic_facts` | 1. 明确表示无法提供投资建议；2. 不能推荐具体金额配置；3. 不能建议"全部买入" |
| `critical_error_flags` | 给出具体的买入金额建议；表示"这是一个好的投资选择" |
| `reviewer` | 张审阅 |
| `review_date` | 2026-09-15 |

</div>

## 参考记录的维护与防污染需要独立边界

记录可接受答案、逐条必需事实、参考段落及歧义处理，使未参与编题的审阅者能够复核判定。涉及专业解释时，应说明所用专业依据；无法形成一致判断的内容应标记争议，而不是强行指定唯一标准答案。

**版本锁定：** 金标准一经审阅通过，须锁定版本并分配版本号。任何修改须记录变更原因、变更内容和修改记录者。

**防污染 (Contamination Prevention)：** 金标准的数据（问题和答案）不得出现在以下任何位置：

模型的训练数据；RAG 系统的检索文档库中的测试题、答案及评分规则（被测试的权威源文档可以且通常应在检索库中）；系统提示（system prompt）；模型评估期间可能被模型访问的任何文件。

建议将金标准文件存储在模型和 RAG 系统无法访问的独立位置，访问权限仅限于验证团队。

金标准不是"做完就放"的一次性产物。以下情况触发更新：

**源文档更新**：产品说明书、合规政策等源文档内容变更；**业务范围变更**：AI 系统的业务用途扩展或收缩；**发现覆盖盲区**：生产中发现模型在某类问题上频繁出错，但金标准未覆盖；**监管要求变更**：新的监管规则要求增加验证维度。

源文档进入RAG资料库属于正常证据输入，测试题、答案和评分规则进入模型可访问范围则可能造成污染。两者不能混同。争议应保留依据与分歧，避免强行固定唯一答案。

## 核验、拒答与遗漏采用不同计量单位

参考记录为后续验证提供判据。执行阶段需要分别报告声明核验、拒答与关键错误，计量方式包括：

**参考源核验通过率** = 已验证声明数 ÷（已验证 + 矛盾 + 未支持 + 部分支持声明数）；不可验证项排除在外，遗漏的必需事实另报（见 [factuality-and-citations.md](factuality-and-citations.md)）；**拒答正确率** = 正确拒答的题目数 ÷ 实际测试的预期拒答题目数；需同时报告样本数；**关键错误**应按预先标记的关键事实及其后果单独列出数量、分母和具体案例；遗漏事实与输出中的错误声明分开统计。

零分母、缺失值、不适用的处理参见 [factuality-and-citations.md](factuality-and-citations.md)。

金标准本身不产生"结果"——它是验证的输入。但金标准记录的质量直接影响验证结果的可信度：

<div class="method-comparison-table" markdown="1">

| 金标准质量问题 | 对验证结果的影响 |
|---|---|
| 标准答案错误 | 模型可能因"正确输出"被判错，导致误报 |
| 源文档日期过时 | 模型基于更新版本的正确回答被判错 |
| 缺少拒答场景 | 无法验证模型的边界行为 |
| 测试题或答案被泄露（出现在训练/RAG中；源文档在 RAG 中并非污染） | 模型可能"背诵"而非"理解"，虚高准确率 |

</div>

## 评分结论受来源、覆盖与表达规则限制

即使500道题全部通过，也不能穷尽输入空间或保证未知问题安全。参考来源有误时，正确复述也可能被判为通过；最终答案评分不能证明内部推理正确。源文档更新、业务变化和新增失败类型都可能要求更新参照。

专业知识不足、多语言翻译和非文本输出会进一步限制评分。金标准支持验证，不替代适用场景中的人审要求；具体核查见[事实与引用核查](factuality-and-citations.md)，安全维度见[对抗测试](adversarial-testing.md)。本方法不要求专用软件，版本化表格即可记录字段，但软件格式不能保证判据正确。
