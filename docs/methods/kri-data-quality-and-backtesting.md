# 风险指标核对：计数边界、数据溯源与告警回测

面板显示“核验通过率92%”，仍可能缺少抽样范围、不可验证项或事件标签。**关键风险指标KRI只有在计数单位、分子分母和数据路径明确时才能解释；回测还要把告警与独立确认的事件匹配。** 初始均值或红黄绿状态不会自动成为合格标准。

24EC55第13(d)段涉及持续监测与记录，适用说明见[通函导读](../regulatory/24EC55.md)。KRI是实现选项之一，本文不规定统一指标、阈值或监测周期。

<p class="article-meta">参考方法 · 本文更新：2026-10-11 · 来源核实：2026-09-30 · 合成教学材料，未执行测试，不构成统一阈值、频率或职责要求。</p>

## 参考源核验案例先固定分子与分母

<div class="method-comparison-table" markdown="1">

| 参数 | 值 |
|------|-----|
| 本观察窗口审查样本数 | 100条（合成抽样） |
| 可对照参考源的事实数 | 850 |
| 已验证 | 782 |
| 与源文档矛盾 | 23 |
| 源文档未支持 | 45 |
| 部分支持 | 0 |
| 不可验证 | 120（不纳入分母） |

</div>

```text
参考源核验通过率 = 782 ÷ (782 + 23 + 45 + 0) = 782 ÷ 850 = 92.0%
```

**结果解释：** 92%只说明这 850 个可对照参考源的事实中有 782 个得到确认；23 个矛盾和 45 个未支持均未算作通过，后者不等于外部事实错误。另有 120 个不可验证项，须单列。若样本按层过采样，应按预先定义的抽样权重估计总体；以上简单计数仅是本合成样本的比例。没有预先约定的评分目标与错误代价，不能把 92%直接解释为“正常”或绿色。

观察窗口中100条抽样输出产生850条可对照声明，计量单位是声明而非输出。若从错误声明数推导输出错误率，还需按输出关联，不能直接换分母。

## 定义与特殊值处理保证跨期可比

<div class="method-comparison-table" markdown="1">

| 输入项 | 说明 | 数据来源示例 |
|--------|------|--------|
| KRI定义 | 指标的业务含义、公式、适用边界和数据来源 | 指标说明及计算定义 |
| KRI数据源 | 数据所在系统、字段、时间戳及采集限制 | 数据字典、接口或导出记录 |
| 历史KRI数据（如有） | 用于比较指标变化的历史观测 | 对应数据源的版本化记录 |
| 事件证据 | 与指标告警相对应的、独立确认的风险事件 | 事件记录及判定依据 |

</div>

每个KRI应有明确的分子和分母定义。模糊的定义导致不一致的计算。

<div class="method-comparison-table" markdown="1">

| 元素 | 定义 |
|------|------|
| 分子 | 在抽样审查中与预定参考源一致的原子事实数 |
| 分母 | 在抽样审查中可对照参考源判定的事实数：已验证、矛盾、未支持及部分支持；排除不可验证项 |
| 零分母处理 | 如果当期无可验证的原子事实（如所有输出均为纯建议性内容），标注为「N/A」而非0% |
| 数据来源 | 事实核验记录中的逐项判定及对应参考源 |

</div>

该比例只说明样本声明与选定参考源的一致情况，不证明参考源本身正确，也不把“未支持”直接解释为外部事实错误。若抽样过度抽取某些层，按抽样设计使用权重；简单计数仅代表未加权样本结果。

<div class="method-comparison-table" markdown="1">

| 陷阱 | 示例 | 修正 |
|------|------|------|
| 分子/分母不匹配 | 分子是「观察窗内发现的错误数」，分母是「观察窗内全部输出数」——但审查是抽样，分子是审查样本中的错误 | 明确：分子 = 审查样本中发现的错误数；分母 = 审查样本总数 |
| 零分母未处理 | 分母 = 观察窗内对客输出数，但该窗口内无对客输出 | 预定义：分母=0时标注「N/A」，不计算比率 |
| 「不适用」与「0」混淆 | 某类KRI对该用例不适用（如RAG检索质量对非RAG系统），但记录为0% | 使用独立的「N/A」标记，不与数值混淆 |
| 时间窗口不明确 | 「最近一段时间」——起止边界是什么？ | 记录明确起止日期及窗口选择依据 |

</div>

<div class="method-comparison-table" markdown="1">

| 特殊值 | 含义 | 处理方式 |
|--------|------|----------|
| **0（零）** | 计算结果确实为零（如该观察窗未检出错误） | 正常记录——这是一个有效值 |
| **N/A（不适用）** | 该KRI不适用于此用例 | 单独标记，不在汇总中计为0 |
| **NULL/缺失** | 数据未收集、系统故障导致无法计算 | 单独标记——表示数据质量问题 |
| **未确定 (Undetermined)** | 数据存在但无法确定其可靠性 | 单独标记——表示需要数据质量审查 |

</div>

某观察窗口内，对客 AI 输出为零，因此事实核验通过率没有可计算分母；抽样审查无法执行。

<div class="method-comparison-table" markdown="1">

| KRI | 观测值 | 标注 |
|-----|--------|------|
| 参考源核验通过率 | N/A | 本观察窗口无对客AI输出，指标不适用 |
| 越界事件数 | 0 | — |
| 第三方API延迟 | N/A | 该窗口无API调用 |

</div>

**注意：** 「N/A」不等于 0，也不应计入数值汇总。它表示这个窗口没有适用观测；是否影响跨期比较，取决于比较窗口及缺失机制。

## 数据路径应能够从汇总追溯原始判定

每个KRI应记录其完整的数据链路：

```text
KRI指标 → 判定字段 → 来源系统/文件 → 筛选与计算逻辑 → 数据时间戳
```

<div class="method-comparison-table" markdown="1">

| 环节 | 值 |
|------|-----|
| KRI指标 | 参考源核验通过率 |
| 计算字段 | 原子事实判定结果（已验证/矛盾/未支持/部分支持/不可验证） |
| 来源系统 | 合成的事实核查记录 |
| 来源表/文件 | `fact_check_results` 表，`judgment` 字段（教学字段名） |
| 抽取逻辑 | 分子：`count(*) WHERE judgment='已验证' AND review_period=:period`；分母：`count(*) WHERE judgment IN ('已验证','矛盾','未支持','部分支持') AND review_period=:period` |
| 数据时间戳 | 记录原始判定与汇总所依据的更新时间，便于复核延迟 |
| 核对日期 | 记录数据与定义最后一次比对的日期 |

</div>

数据时间戳还需反映标签完成和更新延迟。仅验证汇总公式，不检查记录是否完整或被修改，无法证明采集可靠。采用版本化导出或逐题记录，可以核对筛选、去重与聚合是否改变计数对象。

## 待确认告警、误报与漏报采用不同分母

将告警与同一观察范围内经核验的风险事件对照，区分已确认误报、漏报和仍待核验的告警：

<div class="method-comparison-table" markdown="1">

| 概念 | 在KRI语境下的含义 | 示例 |
|------|------------------|------|
| **未确认事件告警** | 已触发但在规定核验窗口内尚未关联到已确认风险事件的告警 | 数据延迟使核验通过率暂时显示较低，随后核对发现该期没有性能退化 |
| **False Positive（已确认误报）** | 观察单元经完整核验为无风险事件，但 KRI 触发告警 | 同一事件观察窗内无对应风险事件，且核验已完成 |
| **False Negative（漏报）** | 实际发生了风险事件但KRI未触发告警 | 一次严重事实错误导致客户投诉，但该错误未被抽样覆盖，KRI正常 |
| **True Positive（正确告警）** | KRI触发告警且确实发生了风险事件 | 准确率持续下降，KRI告警，调查发现模型版本升级引入了新错误 |
| **True Negative（正确安静）** | KRI未触发告警且未发生风险事件 | 系统正常运行，KRI在阈值内 |

</div>

**未确认事件告警比例：**

```text
未确认事件告警比例 = 尚未关联已确认风险事件的告警数 ÷ 总告警数
```

该比例的分母是全部已触发告警，不是所有实际无风险的观测单元；因此它既不是经典假正率（FPR），也不等于已确认的误报比例。尚未完成事件核验的告警仍可能只是待定。经典 FPR 的分母是所有经完整观察窗判定的实际负例：`FPR = 实际负例中触发告警的观察单元数 ÷ 实际负例观察单元总数`。须说明观察单位及事件标签规则；若一个单元可能产生多次告警，应先固定计数单位。高比例可能降低告警的解释价值，但不能只靠它推断使用者会忽略告警。

**漏报率分析：**

```text
漏报率 = 未触发告警的已确认风险事件数 ÷ 同一观察范围内的已确认风险事件总数
```

高漏报率提示该 KRI 对已观察到的风险事件覆盖不足；事件定义、匹配规则和核验窗口会影响结果。

将告警与后续确认的事件对照；观察窗需考虑事件标签延迟和样本量，不设统一周期。

## 初始基线与阈值需要事件证据持续校准

某 KRI 仅有三个相邻窗口的核验通过率：

<div class="method-comparison-table" markdown="1">

| 窗口 | 参考源核验通过率 | 已知情况 |
|------|-----------|------|
| W1 | 88% | 合成示例 |
| W2 | 85% | 有提示配置变更，但样本波动也可能影响结果 |
| W3 | 91% | 合成示例 |

</div>

三个窗口均值为 88%，但样本分母、抽样设计和逐条配对结果均未给出，因此无法估计均值的不确定性，也不能从三个百分比推出可靠阈值。W2 与配置变更同时发生只是调查线索，不能据此认定变更导致下降。

当KRI刚开始运行时，没有历史数据来估计常见波动。可按证据成熟度分阶段建立初始基线：

<div class="method-comparison-table" markdown="1">

| 阶段 | 方法 | 可解释的产物 |
|------|------|------|
| **观察** | 检查数据覆盖、标签延迟、季节性和已知事件；不要把初始分布直接称为“正常” | 带缺失、版本和事件说明的基线样本 |
| **初步校准** | 以有代表性的参考窗口估计波动，并检验候选告警规则对已知事件的响应 | 临时调查信号及其假设，不是合格线 |
| **持续复核** | 结合新增数据和真实事件，检查阈值是否仍有区分力 | 校准依据、未确认事件告警比例和漏报的不确定性 |

</div>

**解释边界：** 有风险事件的窗口应单独标记；排除它们会改变所估计的“常态”分布，需同时说明包含与排除时结论是否改变。样本不足时报告宽的不确定性，不给出看似精确的通用阈值。

校准应比较与目标相符的历史窗口和事件记录，说明纳入与排除条件。系统重大变更、标签延迟变化或真实事件揭示覆盖不足时，应重新检查规则；阈值调整同时记录对已知事件检出及误报的影响，避免只让面板变绿。

## 面板状态不能替代样本与事件解释

单独呈现“通过率 98%”或红黄绿状态无法复算，也不能说明样本量、错误类别或阈值依据。至少要同时给出观察窗、公式、分子和分母、未决/缺失/不可验证项、抽样设计，以及阈值的来源。告警—事件匹配还需给出事件核验窗，并把“尚未确认”与“已确认没有事件”分开；否则所谓误报可能只是尚待判断。

指标未告警只表示既定规则未触发，不能排除未覆盖风险；告警也可能来自数据延迟或波动。低漏报率只描述已定义并确认的事件范围。原始数据可靠、来源适用和事件核验仍需分别复核。

抽样权重见[分层抽样](stratified-sampling.md)，声明判定见[事实与引用核查](factuality-and-citations.md)，观察边界见[监测与漂移](../concepts/monitoring-and-drift.md)。本方法不绑定平台，数据溯源与告警—事件匹配能力比单一图表外观更重要。
