# RAG 分层诊断：证据遗漏、过期资料与生成误用

回答错误时直接更换模型，可能绕过真正的缺陷：例外条款没有进入上下文，或过期规则被排在前面。**RAG分层诊断先确定回答需要的有效证据，再比较检索候选、实际上下文和生成声明，最后用受控替换缩小调查范围。** 指标用于描述发现，不能单独确定根因。

## 主规则与例外共同决定答案

教学资料库包含D1旧规则、D2当前主规则、D3当前例外和D4其他主题。测试问题需要D2与D3，当前用户获准读取两份资料。D1即使措辞相似，也不能作当前答案依据。先由人工核对日期、访问身份和必要声明，形成可复查的相关集合 `{D2,D3}`。

若只根据查询词标注“相关”，旧规则可能被误当成好结果。相关性应结合问题日期和适用对象解释，权限则独立核对；真实资料也可能不允许当前用户使用。关于证据条件的详细解释见[RAG概念页](../concepts/rag.md)。

## 检索指标与生成支持率描述不同缺口

合成检索前3位为D2、D1、D4，命中当前相关集合中的1份。因此 `Recall@3=1/2=50%`，`Precision@3=1/3≈33.3%`。召回率显示当前例外缺失，精度显示前3条中只有1条属于有效相关资料；过时资料1条仍应单列，避免把时效风险埋在所有不相关项中。

回答又包含4个可核查声明，3个获有效来源支持、1个误用D1，声明支持率为 `3/4=75%`。这是本例按声明二元计分的定义，不等于任何工具同名指标的默认算法。这个分数不说明遗漏的D3已被覆盖：检查已说内容和检查必需内容需要分别进行。

| 观察对象 | 本例发现 | 下一步证据 |
|---|---|---|
| 检索候选 | D3未进入前3位 | 入库、分块、查询、索引与排序记录 |
| 资料适用性 | D1过期却进入结果 | 版本、生效日期与过滤条件 |
| 生成声明 | 1条误用D1 | 实际上下文、提示和声明对应来源 |
| 必需信息 | 当前例外没有得到完整处理 | 金标准中的例外条件及回答覆盖 |

## 受控证据替换缩小调查范围

保持问题、模型和提示尽量相同，直接把D2+D3作为上下文。错误消失时，优先调查检索及组装；错误仍存在时，继续检查提示、例外整合和生成输出。替换可能同时改变长度、顺序和噪声，因此它增加某条调查路径的证据，不能证明唯一原因。

再只给D2，观察模型是否承认信息不全，还是把一般规则当成无例外的答案。对没有D3访问权限的用户单独运行，核对D3不应进入上下文；先交给模型再要求“不透露”，并不构成可靠访问隔离。

短块与长块比较也应同时观察完整性和噪声。条款拆分可能割裂主规则与例外，长块则可能带入无关信息或触发截断。跨文档答案应保留文档及章节关系，重复材料可能挤掉关键例外，排序分数也不能证明资料有效。

## 组件修复后仍需完整系统复测

[检索评估](rag-retrieval-evaluation.md)和[生成评估](rag-generation-evaluation.md)分别解释指标与分母。诊断后应用同一判据复测不同日期、身份、缺失和冲突资料；只重复已经修好的问题，会低估未知场景错误。完整路径见[RAG教学专题](../topics/rag.md)。

SFC [24EC55附录第9–10段](https://apps.sfc.hk/edistributionWeb/api/circular/openAppendix?lang=EN&refNo=24EC55&appendix=0)讨论整合、组件测试与引用问题；本文演算并非监管附录案例，不提供合格线。

## 辅助工具的能力与适用范围

检索与生成评分能力可以把召回、支持程度等观察应用于更多题目；调用链记录则用于还原实际候选和上下文。[Azure RAG evaluators](../tools/azure-rag-evaluators.md)提供部分评估实现选项，评分需校准到人工判据。同名分数的算法和输入可能不同，不能直接互换，也不能凭自动评分证明权限正确。
