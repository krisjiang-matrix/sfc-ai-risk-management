# 26EC32 通函解读：SFC AI 增强型网络安全威胁要求（知识导读）

攻击者可以利用 AI 增强网络攻击，因此机构自身没有部署 AI，也可能面对相关威胁。**26EC32 的网络风险范围与24EC55的模型使用范围应分别判断。** 本页先区分一般网络准备与使用 AI 时的额外风险，再定位控制要求及附录中的实施条件。

> 本页先区分不以机构自用 AI 为前提的网络风险要求，与使用 AI 模型时的额外风险，再定位正文和附录。这里是原文导读与技术关联，不展开组织审批流程或机构模板；适用对象和条件见下文。

## 网络威胁范围与机构自用 AI 的区别

第1、3段针对持牌法团、SFC持牌VATP及关联实体的网络风险准备，并不以机构自己使用模型为前提。第8段才进一步处理机构使用AI语言模型时带来的额外风险。

## 正文要求/期望

| 定位 | 解释 |
|---|---|
| 第3段，第1页 | 高管及MIC-IT最终负责；框架变更须适当检视批准并正确及时实施 |
| 第5–6段，第2页 | 稳健且及时更新的控制；资产/组件清单标外露、业务关键和第三方依赖，更新足以支持新情报下当日优先排序和遏制决定 |
| 第7–8段，第3页 | 检视A–E五方面；使用AI时覆盖模型对抗、泄露、系统提示覆盖并衔接24EC55 |
| 第9段，第3页 | 已知漏洞及时处理，紧急/关键修复有非例行流程及资源；没有统一补丁天数 |
| 第10–11段，第3–4页 | 按用户/设备/特权/网络可能失陷设计；最小权限、可行时微分段、不可信输入不得改指令/触发特权、高影响maker-checker |
| 第12段，第4页 | 强化客户交易和系统活动异常监测及威胁情报能力 |
| 第13段，第4页 | 初始/持续供应链风险治理，考虑AI增强攻击 |
| 第14–16段，第4页 | 响应和应变计划、快速升级及预先规划遏制，定期桌面/模拟等演练 |
| 第17段及脚注8，第5页 | 定期备份及可用性；电子交易持牌法团和VATP至少每日，不能扩展成所有机构统一每日要求 |
| 第18段及脚注9–10，第5页 | 按适用操守准则/VATP指引及时通知重大网络安全事件与攻击 |

以上标记为`[监管要求/期望]`。治理、批准、通知和响应流程仅供原文定位；本库展开不可信输入、权限、模型对抗与供应链相关知识。
