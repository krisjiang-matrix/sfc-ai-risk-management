# 26EC35 通函解读：互联网交易强认证与异常监测（强认证最迟 2027-07-08）

**26EC35 处理互联网交易认证与监测专项，不是所有 AI 应用的通用实施清单。** 适用业务确认后，还须分别阅读认证、通知、监测与响应的时间安排；标题中的强认证期限不能代替其他措施的实施期望。

> 本页按适用对象、正文措施和附录方案整理互联网交易专项要求，并区分不同实施时间。若业务边界不清楚，先看[适用范围矩阵](applicability.md)，再核对下方条款定位；这里不设计机构审批或账户处置流程。

## 适用对象

`[监管要求/期望]` 第1段及脚注1–2（第1页）：互联网券商及SFC持牌VASP。互联网券商定义为从事互联网交易的相关第1、2、3类持牌法团，亦包括第9类**仅在通过其互联网交易设施分销所管理基金的范围**。脚注2说明当时VASP指VATP。

普通内部投研/组合系统的资管公司不能仅因第9类牌照、互联网办公或使用AI而被纳入。详见[范围矩阵](applicability.md)。

## 正文定位

| 段落/页码 | 解释，均须保留条件 |
|---|---|
| 第4–6段，第2页 | 登录、设备注册/绑定保护；按平台及风险选择适当方法；已经绑定的设备不要求现有客户重新绑定 |
| 第7–9段，第2–3页 | OTP不视为抗钓鱼方法；passkey和稳健绑定设备为方案例子，设备绑定登录还须额外认证因素 |
| 第10段，第3页 | 一般不应超过三个passkeys及/或三个设备；超过时须适当评估，不是绝对禁令 |
| 第11–12段，第3–4页 | 不让客户关闭会话超时；30分钟是示例，延长有业务理由和密切监测条件 |
| 第13–14段，第4页 | 及时通知成功登录及高风险账户活动、适用时多渠道，提醒客户报可疑活动 |
| 第15段，第4页 | 强烈鼓励重大变更/异常活动获得客户确认后才继续交易；保留“strongly encouraged” |
| 第16(a)–(b)段，第4–5页 | 交易阈值参考客户画像/历史、账户、设备、登录；红旗、足够设备日志和及时跟进 |
| 第17–18段及脚注17，第5页 | 黑客事件立即遏制、保护、通知受影响客户，并立即报告SFC；详细报告、RCA和整改 |
| 第19–20段，第5–6页 | 客户钓鱼风险教育、账户凭据保护和良好安全习惯 |
| 第24–25段，第7页 | 高管/MIC责任及保护客户免受盗窃欺诈等损失的内控责任 |

## 附录：技术方案与实施标准

**A，第1–2页：Passkey。** 第1–3段解释公钥密码学及与真实站点/应用绑定。选择该方案时，“Expected standards”要求适当FIDO认证、强身份核实的注册、额外passkey的授权、撤销/恢复、丢失指导和同步风险控制。

**B，第2–4页：Device binding。** 第4–6段及其实施标准说明设备安全关联、弱验证导致冒绑风险、稳健验证与失设备处理；12个月期满后只能以稳健验证绑定。第3–4页给出passkey、内部记录生物识别、身份证明及现场核实等示例。

正文第8段和附录方案例子标`[监管附录示例]`；方案下明确“should”的标准另标`[监管要求/期望]`。不能将设备原生指纹/面容解锁等同附录示例中的后台身份记录核验，也不能要求所有机构统一收集生物资料。

正文采用的FIDO、passkey属于相关技术标准/方案；任何厂商实现仍非SFC指定产品。
