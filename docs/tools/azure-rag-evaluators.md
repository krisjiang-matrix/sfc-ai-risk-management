# Azure AI 评估器：groundedness 等分数代表什么

回答流畅、切题和有证据支持，是不同的质量维度。某项指标提高，并不意味着产品事实和适用日期也正确。**Azure AI 评估器将这些维度分别评分，用于比较回答和检索质量。** 使用前必须明确每项分数所依据的数据与判断，避免将自动评分当作业务结论。

## 不同质量维度使用不同的评估依据

[技术解释] Azure AI Evaluation SDK 提供数学指标和 AI 辅助评估器；RAG 相关能力包括 groundedness、relevance、检索及完整性等。不同评估器需要不同数据，不能仅凭字段名称把它们当成等价指标。[官方 SDK 指南](https://learn.microsoft.com/en-us/azure/foundry-classic/how-to/develop/evaluate-sdk)

本页据 Foundry classic 文档核实，部分功能标为 preview，新旧门户和 API 可能不同。运行时固定 `azure-ai-evaluation` 版本，再确认相应文档；本页未确认最新稳定 SDK 版本，未执行云端调用。

## 评估字段与模型服务的数据边界

问题定义任务，回答是待检查对象，上下文说明回答可依据的材料，人工参考则表达经核对的预期内容。它们不能互相替代：把模型回答复制成参考答案，会失去独立核验；补入应用未实际收到的上下文，也会掩盖检索遗漏。数据准备应先确认字段来自同一次运行，再按所选评估器的定义提交。

当一项评分异常时，首先区分输入缺失、服务执行失败与回答质量问题。只有成功完成、所需数据齐全且判据适用的记录，才进入质量比较。否则总体低分可能只是配置故障，总体高分也可能来自被静默排除的困难样本。

输入包括 query、response、context，部分指标还需 ground truth。配置指定裁判 endpoint、deployment、API version 及凭证；数学指标不一定调用模型，AI 辅助评估器可能将上下文和答案传给模型服务。批量结果可保存在本地，也可上传 Foundry 项目，二者数据路径不同。

使用官方配置类型与环境变量，不将省略号 endpoint 或虚构项目连接串作为可运行示例。凭证、模型部署和支持的评估器须先验证；需要的字段缺失不应解释为低质量，也不宜静默转成空文本后继续评分。

## 用支持与矛盾两类回答校准判据

[教学示例] 下列资料与回答均为合成内容。先由人工写出参考判据，再将每行的 query、context、response 按所选版本的评估器要求传入；缺少字段时停止评分，不把空值当作低分。

<div class="tool-evidence-table" markdown="1">

| 问题 | 检索资料 | 待评回答 | 人工判据 |
|---|---|---|---|
| 基金 A 管理费是多少？ | 管理费 1.5%；主要投资亚太股票。 | 管理费为 1.5%。 | 有资料支持 |
| 基金 A 主要投资什么？ | 管理费 1.5%；主要投资亚太股票。 | 主要投资美国国债。 | 与资料矛盾 |

</div>

测试前确认评估器所需字段、裁判模型和 endpoint；若使用 AI 辅助评估器，核对上下文和回答是否会传给外部服务。上表给出的是**人工预期判据**，本页没有 Azure 实际分数，也不声称软件必定正确区分两行。运行后应将逐题结果与人工标签对照，记录误判和执行错误。

一段流畅的错误回答可有较高 fluency／coherence；与过期资料一致的回答可有较高 groundedness。评分理由帮助发现问题，却不是独立事实证据。需要与人工标注比较误判、逐题复核及固定裁判版本，参见 [模型裁判校准](../methods/judge-calibration.md)。

SDK 开源许可与 Azure 云服务、裁判模型费用及条款分开确认。云端评分可能涉及敏感上下文、区域与日志；本页不把全部服务称为开源工具。替代为 [Ragas](ragas.md)、[Promptfoo](promptfoo.md)、[人工生成评估](../methods/rag-generation-evaluation.md)。
