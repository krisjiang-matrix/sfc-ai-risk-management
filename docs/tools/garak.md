# garak：LLM 脆弱性扫描怎样读结果

## 挑战输入与检测器如何形成扫描结果

[技术解释] garak 通过目标接入、挑战输入生成、响应检测和执行组织四个环节探索 LLM 失效，包括提示注入、越狱、泄露、幻觉等。官方描述包含静态、动态和自适应探针，数量和可用类别随版本变化。[官方仓库](https://github.com/NVIDIA/garak)

这四个组件具有不同责任。generator 负责接入被测目标，probe 产生挑战输入，detector 判断响应是否满足某种失效条件，harness 组织执行与判定。输入生成与结果识别均可能存在覆盖缺口，因此结果必须保留具体输入、原始响应和检测依据，才能检查命中是否符合应用实际边界。

例如响应引用攻击文本以解释防御方法，可能触发关键词检测，却没有泄露任何秘密。反之，实际泄露可能采用检测器未识别的表达。**检测器命中是候选发现，人工核对后的失效才是当前样本中的确认结果**；两者应分别计数。

输入为目标接口、探针、检测器及生成参数；输出是运行记录和命中。它不直接证明业务事实准确性、RAG 权限隔离、所有 Agent 动作安全或整体合规。与 [Promptfoo](promptfoo.md) 的选择根据目标接入、覆盖和复现要求，避免用工具聚合分数做排名。

## 目标调用及检测记录的数据路径

测试输入 → generator → 模型响应 → detector → JSONL 运行记录。目标可能在本地或云端，某些检测器还调用另一模型，均需核实数据去向。使用合成内容和测试目标；有状态 Agent 应隔离工具动作并重置记忆。命中日志可能含攻击文本及泄露片段，分享前脱敏。

已核实 [0.17.0 release](https://github.com/NVIDIA/garak/releases)，核心 Apache-2.0；Python、依赖及插件环境要求按该版本安装文档确认。

## 用空模型核对工具链路

[教学示例] 仅演示内置空模型与空探针链路。本次重构未运行以下软件，不能视为已复现安全测试。

```powershell
python -m pip install garak==0.17.0
python -m garak --list_probes
python -m garak -m test.Blank -p test.Blank
```

官方 README 给出了 blank generator/probe 测试形式。它验证的是工具链路，空模型结果没有真实系统的安全意义。运行后按终端报告的实际路径查看记录，不假设当前目录必有 `garak_runs`。配置、attempt、eval 等记录结构按 [结果文档](https://docs.garak.ai/garak) 与所用版本解析；不要把手工示意表当原始 JSON schema。

## 命中比例、精确率与漏报的不同分母

[教学示例] 下列 100 条响应与标签均为合成数据，不是前述 blank generator/probe 命令的输出。检测器标记 12 条；人工逐条回看这 12 条，其中 8 条符合预先定义的失败条件，4 条为误报。另从 88 条未命中响应中抽查 20 条，发现 1 条漏报。

<div class="tool-evidence-table" markdown="1">

| 审查范围 | 已审数量 | 确认失败 | 判读 |
|---|---:|---:|---|
| 检测器命中 | 12 | 8 | 精确率 `8/12≈66.7%`；另 4 条误报 |
| 未命中中的演示抽样 | 20 | 1 | 抽中样本的失败比例 `1/20=5%`；不等于全部 88 条的漏报率 |

</div>

因此，12/100=12% 是**命中比例**，8/12 是命中中的精确率；它们不是整体失败率或召回率。要估计漏报，须按目标分布抽查未命中项并说明抽样设计；本例的 20 条只是演示分母，不是通用抽样比例。不能把 88 条未命中都判为安全。

[参考方法] 回查输入、原始响应、检测依据、应用目的和实际工具动作。关键词出现、讨论防御方法、引用攻击文本都可能被检测器误判。对高影响命中优先复现，再用代表性抽样检查其余记录；抽样比例按误差目标及分布确定，不采用固定 10–20% 的通用规则。

## 未命中记录与整体安全的区别

没有泄露命中不证明数据安全：未覆盖的提取方法、语言、上下文或查询预算均可能改变结果。扫描分数不是事实准确率；大量失败也可能来自错误配置、目标不可达或评分失败。替代为 [PyRIT](pyrit.md)、[Promptfoo](promptfoo.md) 或人工多轮挑战。
